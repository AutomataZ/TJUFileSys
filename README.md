# TJUFileSys

操作系统课程设计 —— 类 UNIX 二级文件系统（misakifs）

用一个普通文件 `myDisk.img` 模拟 UNIX V6++ 的一张磁盘，在该逻辑磁盘上定义二级文件系统的
数据结构，并提供命令行界面完成文件系统的基本操作。

---

## 一、运行说明

### 环境要求

- Linux / WSL
- g++（支持 C++11）
- CMake 3.16 或以上

### 步骤

**1. 创建磁盘镜像文件（必需，首次运行前做一次）**

程序打开一个 4 MB 的文件 `myDisk.img` 来模拟磁盘。该文件**不会被程序自动创建**，
需要手动建立，否则程序会提示「文件没有正确打开!」并退出：

```bash
cd TJUFileSys
truncate -s 4M myDisk.img
```

**2. 编译**

```bash
cd code
mkdir -p build && cd build
cmake ..
make
```

**3. 运行**

```bash
cd code/build          # 必须在 build 目录下运行
./main
```

> **为什么必须在 `code/build/` 下运行？**
> `disk_name` 在 `code/define.h` 中定义为相对路径 `../../myDisk.img`，相对
> **当前工作目录**解析。只有从 `code/build/` 启动才能定位到仓库根目录下的镜像文件。

不使用 CMake 时也可以直接编译（注意按下面的路径放置可执行文件）：

```bash
g++ -std=c++11 -Icode -o code/build/main \
    code/main.cpp code/shell.cpp code/filedir.cpp code/format.cpp \
    code/inode.cpp code/superblock.cpp code/buffer.cpp code/openfile.cpp \
    code/test.cpp code/wirteDisk/wirteDisk.cpp
```

### 使用方式

启动后程序会先自动演示一遍课程设计要求的场景（见「五、演示流程」），随后进入交互模式，
提示符形如 `MF /home/texts >`，输入命令回车执行，输入 `exit` 退出。

### 运行测试

`code/unittest/` 下是一套不依赖第三方框架的单元测试，覆盖成组链接法、6-2-2 混合索引、
缓存 LRU 与延迟写、文件系统调用层、边界与数据完整性五层。测试自建镜像文件
`unittest.img`（位于当前工作目录），不读 `disk_name`，因此与演示程序互不干扰。

```bash
# 方式一：cmake（构建 unittest 目标）
cd code/build && cmake .. && make unittest && ./unittest

# 方式二：直接调用 g++（无 cmake 环境时）
g++ -std=c++11 -Icode -o code/build/unittest \
    code/unittest/*.cpp \
    code/shell.cpp code/filedir.cpp code/format.cpp code/inode.cpp \
    code/superblock.cpp code/buffer.cpp code/openfile.cpp \
    code/wirteDisk/wirteDisk.cpp
cd code/build && ./unittest
```

`--full` 会额外运行重量级用例（20 万字节大文件，会跑满 6-2-2 索引与多组空闲链）：

| 标记 | 含义 |
| --- | --- |
| `[PASS ]` | 用例通过 |
| `[FAIL ]` | 用例失败，**计入退出码** |
| `[BUG  ]` | 该用例断言的行为尚未达成，属预期结果，不计入退出码 |
| `[FIXED]` | 该用例断言的行为已经达成，可把它改成普通用例 |
| `[SKIP ]` | 需要 `--full` 才能运行的用例 |

退出码只由普通用例决定，因此无论是否加 `--full` 都返回 0：既让用例能把尚未达成的行为
一并记录下来，又让退出码始终真实反映代码是否变差。每个这样的用例，注释里都写明了它
断言的是哪一条行为。

## 三、磁盘布局

| 区域 | 块号 | 大小 |
| --- | --- | --- |
| SuperBlock | 0 ~ 1 | 2 块（1024 B） |
| Inode 区 | 2 ~ 191 | 190 块（1520 个 inode） |
| 文件数据区 | 192 ~ 8191 | 8000 块 |
| 合计 | 0 ~ 8191 | 8192 块（4 MB） |

约定：

- 每块 **512 字节**
- 每个 inode **64 字节**，一个盘块正好容纳 **8 个** inode
- inode 号 `i` 的定位：磁盘偏移 = `1024 + i × 64`，**O(1)** 可直接算出
- 盘块号一律是**绝对块号**（0 号就是磁盘的第一块，文件数据区的第一块是第 192 块），
  定位公式只有一个：磁盘偏移 = `blkno × 512`

## 四、核心设计

### 1. 逻辑磁盘的读写

`code/wirteDisk/` 是上层所有代码访问模拟磁盘的唯一入口。磁盘本身是 `DiskFile`——一个
打开着的镜像文件描述符：

```cpp
class DiskFile {
public:
    bool open(const std::string& path);                     // 打开已有镜像, 不创建
    static bool create(const std::string& path, int size);   // 建立(或清空)镜像
    void sync();                                             // fsync: 让已写下去的落到设备上
    void close();
};

void readDisk (DiskFile& disk, void* buffer, int size, int offset);
void writeDisk(DiskFile& disk, void* buffer, int size, int offset);
```

`offset` 是**相对文件开头的绝对字节偏移**，接口自身不做任何换算，也不认识「块」——
把块号折成偏移是调用方的事（公式见「三、磁盘布局」）。传负数表示**不移动读写位置**，
就地读写（沿用文件流的语义）。

用文件描述符而不是 `std::fstream`，是因为流还有一层用户态缓冲：`write` 返回只说明数据
进了缓冲区，与"落到设备上"是两回事，而落盘屏障要的正是后者——`fsync()` 需要拿到 fd。
读写共用同一个文件位置（`lseek` + `read`/`write`），与流的行为一致，负偏移的语义正依赖
这一点。屏障的使用方式见「四、8 提交点与落盘顺序」。

### 2. SuperBlock 与 Inode 区

SuperBlock 占磁盘前 1024 字节：

| 字段 | 含义 |
| --- | --- |
| `s_isize` | inode 区占用的块数 |
| `s_ninode` / `s_inode[100]` | 直接管理的空闲 inode 个数 / 索引表（栈） |
| `s_fsize` | 数据区盘块总数 |
| `s_nfree` / `s_free[100]` | 直接管理的空闲盘块个数 / 索引表（栈） |
| `load[208]` | 填充字段，凑满 1024 字节 |

**空闲 inode 的分配与回收**：分配时从 `s_inode` 栈顶退栈；栈空时扫描 inode 区，把
`isEmpty()` 的 inode 重新压栈，凑满 100 个后再分配。回收时压栈。

**空闲盘块的分配与回收 —— 成组链接法**：8000 个数据盘块按 100 个一组分组，每组占用
其中一块作为索引块，存放「本组块数 + 100 个块号」。SuperBlock 只保留当前一组的索引。

- **分配**：从 `s_free` 栈顶退栈；当 `s_nfree` 减到 0，说明刚分配的这块本身就是下一组的
  索引块，把它从磁盘读回来填充 `s_free`
- **回收**：压栈；栈满 100 时把当前栈内容写进待回收的块中，该块成为新的索引块

### 3. Inode 与索引结构

Inode 占 64 字节：

| 字段 | 大小 | 含义 |
| --- | --- | --- |
| `d_mode` | 4 B | 文件类型：空 / 普通文件 / 目录文件 |
| `d_size` | 4 B | 文件大小（字节）；目录文件下等于「子文件数 × 2」 |
| `d_addr[10]` | 40 B | 索引表 |
| `load[16]` | 16 B | 填充字段，凑满 64 字节 |

索引采用 **6-2-2 混合索引**：

| 索引项 | 类型 | 覆盖逻辑块号 | 容量 |
| --- | --- | --- | --- |
| `d_addr[0..5]` | 直接索引 | 0 ~ 5 | 6 块 |
| `d_addr[6..7]` | 一级间接索引 | 6 ~ 261 | 2 × 128 块 |
| `d_addr[8..9]` | 二级间接索引 | 262 ~ 33029 | 2 × 128 × 128 块 |

- **索引结构的生成**：`appendBlk()` 追加一个数据块；当某张索引表恰好写满时，自动分配
  下一级索引块并挂到 `d_addr` 上
- **索引结构的检索**：`BMap()` 把逻辑块号映射为物理块号，逐级读取索引块

索引块是**预分配**的：追加第 6 个直接块时就把一级索引块挂到 `d_addr[6]`，第 134 块时挂
`d_addr[7]`，第 262 块时挂二级间接索引块 `d_addr[8]` 并同时备好它的第一张子表，此后每写满
一张子表再备下一张（第 16646 块才轮到 `d_addr[9]`，4 MB 的镜像到不了）。因此「文件恰好占
6 块」也意味着它已经持有一个索引块，而 `d_addr` 中尚未用到的槽位一律是 `-1`。

`d_size` 由 `changeSize(int add)` 维护，它按**增量**累加 —— 调用方传的是「这次增加多少
字节」，而不是目标值。

### 4. 目录结构

目录项 `FileDir` 占 16 字节，写在文件**第一个数据块的开头**：

| 字段 | 大小 | 含义 |
| --- | --- | --- |
| `inode` | 2 B | 该文件（或目录）的 inode 号 |
| `fa_inode` | 2 B | 父目录的 inode 号 |
| `f_name` | 12 B | 文件名 |

目录项之后紧跟文件内容。对目录文件而言，这部分存放的是**子文件的 inode 号数组**，
每 2 字节一个，因此 `d_size / 2` 就是子文件数。根目录的 `inode == fa_inode`。

首块开头这 16 字节既然要留给目录项，文件容量就要按它折算：N 字节的文件占
`ceil((N + 16) / 512)` 块，反过来占 B 块的文件能装 `B × 512 - 16` 字节。0 字节的文件也
必须占一块 —— 否则名字无处可写。目录文件则恒定只占一块（子目录项写满也不扩），它的
`d_size` 记的是子文件数，与盘块数无关。

- **检索**：在当前目录的数据块中线性扫描子 inode 号，逐个读出其目录项比对文件名
- **增加**：`newFile()` 分配 inode 与盘块，写入目录项并更新父目录大小
- **删除**：`fdelete()` 移除目录项，释放 inode 与该文件占用的全部盘块

### 5. 文件打开结构

```
磁盘上的目录项 ──打开──▶ 内存 inode 表 ──关联──▶ 系统打开文件表
```

| 结构 | 容量 | 内容 |
| --- | --- | --- |
| `MemInodeTable` | 100 | 内存 inode（含 inode 号），当前目录下标 `current_dir` |
| `OpenFileTable` | 100 | 打开权限、指向内存 inode 的指针、读写指针 `f_offset` |

- **打开过程**：`FileDir::open()` 在两张表中各追加一项；已打开的文件不重复登记
- **关闭过程**：`FileDir::close()` 在两张表中各删除一项
- **内存 inode 的分配与回收**：`MemInodeTable::append()` / `erase()`

### 6. 高速缓存

内存中设置若干个缓存块，用缓存控制块描述其状态：

| 字段 | 含义 |
| --- | --- |
| `b_blkno` | 关联的盘块号 |
| `load[512]` | 缓存内容 |
| `del_write` | 延迟写标记 |
| `new_create` | 该缓存是否为新创建（内容无效） |

缓存队列按课程要求实现：

1. **LRU 管理**：队列按访问顺序排列，命中时把该块移到队尾，队满时从队首淘汰
2. **尽量重用**：`getBlk()` 先在队列中查找，命中则直接返回，不重复读盘
3. **不能重用时**：淘汰队首（若带延迟写标记则先写回磁盘），再通过底层磁盘接口读入
   该 `blkno` 对应的 512 字节
4. **延迟写**：`Bwrite()` 只写入缓存并置上 `del_write` 标记，真正落盘发生在缓存被淘汰、
   格式化、退出文件系统、**关闭文件**（`fclose`）与**扩容写**（`readWriteFile`）时。
   后两处是提交点，见「四、8 提交点与落盘顺序」。`BufferMgr::flush()` 是"只写回、不清空
   缓存"，提交点用它；`clear()` 则写回并把缓存清空。

`Bread(dev, blkno)` 流程：`getBlk()` 取得缓存 → 若 `new_create` 为真则从磁盘读入
512 字节 → 返回该缓存。

`Bwrite(dev, blkno, buf, offset, size)` 是一次**局部写**：只覆盖 `[offset, offset+size)`，
而回写时整块 512 字节都会写出去。因此它也走 `Bread` 而不是 `getBlk` —— 未命中时先从
磁盘读入块内原有内容，再改写其中一段，构成一次完整的 read-modify-write。若这里用
`getBlk`，未命中的全零缓存会在回写时把块内没参与本次写入的部分清零 —— 文件首块开头那
`sizeof(FileDir)` 字节的目录项（见「四、目录结构」）会因此被抹掉，文件当场从 `ls` 里消失。

### 7. 文件读写

`readWriteFile()` 同时承担读和写：

- 由读写指针算出起始物理块号与块内偏移
- **读**：跨块循环，每块经 `Bread()` 从缓存取内容，拼接成字符串返回
- **写**：若写入范围超出文件大小，先扩容（分配新盘块、更新 `d_size`），再经 `Bwrite()`
  写入缓存并标记延迟写
- 每次读写后更新系统打开文件表中的读写指针 `f_offset`

### 8. 提交点与落盘顺序

这一节回答的是：OS 崩溃或设备掉电之后，盘上那份镜像会是什么样。

**要守住的不变量**：

> 一个 inode 在盘上写着「这个文件有 N 字节」时，它所指向的那 N 字节必须已经在设备上。

反过来的状态不是「丢一次写」那么轻：inode 说文件有 N 字节，而那些盘块里还是上一个主人
的内容（盘块从空闲链分配出去后，新内容一开始只在缓存里挂着），读出来是别人的数据。

`sync()` 是这条链上的屏障，它保证**此前已经完成的写**都落到设备上。屏障本身不构成顺序，
顺序要靠写的先后建立，所以每一处会改变盘上「谁指向谁」的地方都排了一个提交点：

| 提交点 | 位置 | 守住什么 |
| --- | --- | --- |
| 建文件 ① | `newFile` 分配完 inode 与盘块 | 分配记录（空闲 inode 表、空闲块链）先于任何人引用这些资源。同时先把回收来的 inode 体擦成「零字节、无块」，不让上一个主人的 `d_size`/`d_addr` 跟着落盘 |
| 建文件 ② | 写完文件本体（自己的 inode + 首块里的目录项） | 父目录指向它之前，它自己得是完整的 |
| 建文件 ③ | 写完父目录项与父 inode 的 `d_size` | 目录项先于项数。反过来会留下「项数说有 N 项、第 N 项其实是陈旧 inode 号」的幻影目录项 |
| 扩容写 | `readWriteFile` 的扩容分支 | 内容先 `flush` + `sync` 推到设备上，带新 `d_size` 的 inode 头才落盘 |
| 删除 | `fdelete` | 先摘目录项并减父目录项数，再回收盘块与 inode，最后把空闲表 `save` 落盘 |
| 关闭 | `fclose` | 原地覆盖写（不扩容）那条路径在 `fwrite` 时既不写 inode 也不落盘，全靠关闭时把缓存推上设备 |
| 格式化 | `diskFormat` 末尾 | 格式化是整体重建，写完即落地 |
| 退出 | shell 的 `exit` | 清空的缓存与刚写下的 superblock 落盘 |

删除侧的先后与建文件侧相反，理由不同：建文件时目录项必须排在 `d_size` 之前（否则项数
往前跑，多出来的一项是垃圾）；删除时 `d_size` 必须排在搬移目录项之前——先搬完而项数没
减，盘上会出现「最后一项是搬过来的重复项」的目录，那个名字以后再被删一次，就会释放掉
一个还有第二个目录项指着的 inode。

## 六、命令说明

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `fformat` | — | 格式化文件卷 |
| `ls` | — | 列出当前目录内容 |
| `mkdir` | `<目录名>` | 创建目录 |
| `cd` | `<目录名>` | 切换当前目录，支持 `.` 和 `..` |
| `fcreat` | `<文件名> <大小>` | 新建文件，按指定大小预分配盘块 |
| `fopen` | `<文件名>` | 打开文件 |
| `fclose` | `<文件名>` | 关闭文件 |
| `fread` | `<文件名> <字节数>` | 从读写指针处读取内容 |
| `fwrite` | `<文件名> <内容> [字节数]` | 写入内容，省略字节数则写入全部 |

文件名最长 12 字节。
